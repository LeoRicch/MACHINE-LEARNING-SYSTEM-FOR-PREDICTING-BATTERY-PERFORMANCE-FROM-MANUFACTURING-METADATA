# Casimir battery simulation app

Double-click **Start Casimir.cmd**. Keep its window open while using the app. The app opens a local browser at `http://127.0.0.1:8765/` and does not upload data or call a remote prediction service.

## Use the app

1. Use the default cell scenario or expand **Customize scenario**.
2. Select **Initialize simulation**. Wait while the app prepares the result.
3. Read the capacity estimate. Open **View more results** for evaluation charts and explanations.
4. Save a result to revisit it, or download the detailed JSON report.

The installed environment operates offline. The first initialization creates a dataset and compares models if no compatible model is saved. Later initializations reuse the saved pipeline and do not retrain or re-evaluate the final test set. The interface keeps these operations behind the initialization action.

## What the result means

The app predicts a hypothetical lithium-ion cell's initial discharge capacity in mAh from five manufacturing variables. Training and evaluation use **synthetic data** generated by the equation in the corrected research document. Test scores describe performance within that synthetic domain. They do not validate commercial batteries, safety, lifetime, pack capacity, or solar backup duration.

The detailed result shows:

- The current prediction and its noise-free analytical reference.
- MAE, RMSE, R², and MAPE on 400 reserved synthetic records.
- Reference-versus-predicted and residual charts for the reserved batches.
- Model comparison from development cross-validation, kept separate from final testing.
- Optional scenario values, batch metrics, and model provenance.

## Installation and files

The tested environment is 64-bit Windows with Python 3.14.2. Exact library versions are pinned in `requirements.txt`. A project `.venv` keeps dependencies isolated. A local `wheelhouse`, when included, allows dependency installation without internet on the tested platform; otherwise initial installation requires PyPI access. After setup, internet access is unnecessary.

- `web/`: the designed interface and SVG evaluation charts.
- `casimir/`: simulation, validation, learning, storage, and orchestration.
- `server.py`: a loopback-only Python HTTP service.
- `data/models/<run_id>/`: immutable datasets, audit records, fitted pipeline, test predictions, and report.
- `data/latest.json`: compatible model-run pointer and report checksum.
- `data/casimir.sqlite3`: configurations, batches, records, model runs, predictions, and saved results.
- `data/app.log`: diagnostic errors.

The browser frontend preserves the reviewed design. This implementation uses Python's local HTTP server rather than Streamlit to retain that interface. The server is intended for a single-computer academic demonstration; it is not a public hosting service.

## Developer checks

From the app directory, run `.venv\Scripts\python.exe -m unittest discover -s tests -v`. The learning tests run the full experiment once in a temporary directory. To launch without opening a browser, use `.venv\Scripts\python.exe server.py --no-browser`. An alternative port can be supplied with `--port`.

Use only trusted model artifacts created by this app. Configuration, feature order, dependency versions, and checksums are checked before loading. A mismatched artifact is rejected. Keep the `data` directory when moving the installed app. Recreating it intentionally starts a fresh synthetic experiment; do not repeatedly change the generator in response to final test outcomes.

Compatible CSV validation exists in the engine module; a user-facing import workflow is not part of this simplified initial release. Model development controls are intentionally absent from the user interface.
